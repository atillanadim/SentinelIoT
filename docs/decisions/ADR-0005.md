# ADR-0005 — Banco local e política de retenção

**Data:** 2026-11-08
**Status:** aceito

## Contexto

O MVP precisa armazenar eventos, decisões, allowlist, configurações e auditoria
em uma instalação individual, com baixo consumo e sem infraestrutura externa.

## Alternativas

1. SQLite com WAL.
2. PostgreSQL local.
3. Arquivos JSON.
4. DuckDB.

## Decisão

- SQLite em `data/sentineliot.db`.
- WAL, `foreign_keys=ON` e `busy_timeout`.
- Schema versionado com `PRAGMA user_version`.
- Sem ORM no MVP; repositórios explícitos.
- Retenção inicial de 90 dias, configurável e auditada.
- Índices por timestamp, IP de origem e tipo de evento.

## Justificativa

SQLite é suficiente para uma instalação individual, não exige servidor, é
confiável e fácil de copiar. Evita Redis, Kafka, Kubernetes e banco distribuído
no MVP.

## Consequências

- Escrita concorrente limitada.
- CLI e agente precisam de transações curtas.
- Backup deve usar a API de backup ou checkpoint do WAL.
- Migrações futuras precisam de versionamento.
- Retenção e descarte precisam ser testados.

## Riscos

- Corrupção por desligamento abrupto; mitigar com WAL e backup.
- Crescimento do banco em caso de rajada.
- Exposição de metadados se as permissões forem frouxas.
- Consultas lentas se os índices não forem usados.

## Evidência de validação

Pendente: criação do schema, teste de persistência e retenção na Fase 2.
