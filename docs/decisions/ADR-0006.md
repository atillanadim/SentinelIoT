# ADR-0006 — Adaptador de firewall inicial

**Data:** 2026-11-08
**Status:** aceito

## Contexto

O MVP precisa demonstrar contenção temporária sem risco de bloquear a rede
doméstica. O ambiente é Windows para desenvolvimento e Linux para runtime.

## Alternativas

1. `DryRunFirewallAdapter` como padrão e nftables apenas na Fase 5.
2. nftables desde o início.
3. iptables.
4. API de roteador.

## Decisão

- Padrão obrigatório: `DryRunFirewallAdapter`.
- Nenhuma regra real é criada em `observe` ou `dry_run`.
- `NftablesFirewallAdapter` será implementado na Fase 5, somente em VM Linux.
- O adaptador real só opera em tabela/cadeia/conjunto próprio.
- `enforce_enabled` permanece `false` até homologação.

## Justificativa

Começar pelo dry-run permite validar decisões, auditoria e CLI sem risco. A
Fase 5 concentra o risco em um laboratório com snapshot.

## Consequências

- A demonstração do MVP pode ser concluída em dry-run.
- O bloqueio real é uma extensão técnica comprovada apenas em laboratório.
- O adaptador real exige helper privilegiado.
- Testes de firewall não rodam no Windows.

## Riscos

- Pressão para "só testar rápido" em rede real deve ser recusada.
- Uma implementação nftables incorreta pode afetar regras de terceiros.
- A confirmação da regra pode falhar e precisa ser tratada como falha.

## Evidência de validação

Pendente: testes de dry-run na Fase 3 e testes de nftables na Fase 5.
