# ADR-0011 — Topologia de laboratório

**Data:** 2026-11-08
**Status:** aceito

## Contexto

O laboratório precisa ser isolado, reproduzível e adequado a nftables. O host
Windows já possui VirtualBox e uma rede host-only em 192.168.56.0/24, mas essa
rede é usada por outras VMs.

## Alternativas

1. Runtime em VM Linux dedicada, rede host-only nova.
2. Runtime no Windows com Docker Desktop.
3. Runtime em WSL2.
4. Reutilizar VMs e rede host-only existentes.

## Decisão

- Runtime em VM Linux dedicada.
- Rede host-only nova, sugerida 192.168.57.0/24.
- VM `sentinel-lab` e VM `attacker`.
- Snapshots antes de Docker e antes de nftables.
- VMs e rede dedicadas ao SentinelIoT.

## Justificativa

A VM dedicada oferece paridade com produção, permite nftables e isola o
experimento. Uma rede nova evita interferência com outras VMs.

## Consequências

- Provisionamento pendente de autorização.
- Consumo de RAM e disco no host.
- Necessidade de documentar IPs e snapshots.
- Pastas compartilhadas ou clone Git dentro da VM.

## Riscos

- VM com rota para a rede doméstica.
- Conflito de rede com outras VMs.
- Recursos insuficientes no host.
- Esquecimento de snapshot antes de teste de firewall.

## Evidência de validação

Pendente: criação da rede, provisionamento, snapshot e teste de isolamento.
