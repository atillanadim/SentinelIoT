# ADR-0003 — Canal de eventos entre honeypot e agente

**Data:** 2026-11-08
**Status:** aceito

## Contexto

O honeypot precisa entregar eventos ao agente sem expor um listener de rede
desnecessário. O container terá filesystem somente leitura, exceto pelo spool.

## Alternativas

1. Volume compartilhado com JSONL append-only.
2. HTTP interno do honeypot para o collector.
3. Unix domain socket compartilhado.
4. MQTT, Redis ou fila externa.

## Decisão

- Volume de spool montado no honeypot com escrita.
- Agente lê o JSONL e normaliza.
- Cada linha é um evento JSON independente.
- Rotação e limite de tamanho serão definidos na Fase 2.
- O agente deduplica por `event_id`.

## Justificativa

O spool evita um listener adicional, funciona com filesystem read-only e é
simples de testar. Não introduz broker no MVP.

## Consequências

- O spool precisa de permissões restritas no host.
- O collector precisa tratar truncamento, rotação e linhas parciais.
- Eventos podem ser perdidos se o disco falhar; o health check deve detectar.
- O container não precisa de rede para entregar eventos.

## Riscos

- Se o host for comprometido, o spool pode ser adulterado.
- Um honeypot comprometido pode gerar volume excessivo de eventos.
- Linhas malformadas não podem derrubar o collector.

## Mitigações

- Limite de tamanho e rotação.
- Validação estrita de schema.
- Deduplicação e limite de taxa.
- Permissões de arquivo restritas.
- Auditoria de descarte.
