# ADR-0001 — Sistemas operacionais e matriz de suporte

**Data:** 2026-11-08
**Status:** aceito

## Contexto

O host de desenvolvimento é Windows 11. O produto depende de Docker, SQLite,
Python e, na Fase 5, de nftables. nftables não existe no Windows. O MVP precisa
de um ambiente reproduzível e comprovável.

## Alternativas

1. Desenvolver e executar tudo no Windows, com Docker Desktop.
2. Desenvolver no Windows e executar o runtime em WSL2.
3. Desenvolver no Windows e executar o runtime em uma VM Linux dedicada.
4. Desenvolver e executar tudo em Linux desde o início.

## Decisão

- Windows 11 x86_64: edição, lint, mypy e testes unitários rápidos.
- VM Linux dedicada x86_64 (Ubuntu 22.04/24.04 ou Debian 12): runtime oficial,
  Docker, integração, testes de segurança e nftables.
- Produção futura: host Linux homologado, com systemd e helper restrito.

O Docker Desktop no Windows pode ser usado para verificação de CLI, mas não é o
laboratório de segurança.

## Justificativa

A VM Linux oferece paridade com o alvo de produção, permite testar nftables de
forma isolada e evita que o Windows seja o ambiente de segurança do produto. O
Windows continua produtivo para edição.

## Consequências

- É necessário provisionar a VM e a rede host-only.
- O venv do Windows e o venv da VM são separados.
- Pastas compartilhadas e line endings precisam de atenção.
- Testes de firewall só valem na VM.
- O host precisa de recursos para a VM.

## Riscos

- VirtualBox e WSL2/Hyper-V podem competir por recursos.
- Uma VM mal configurada pode ter rota para a rede doméstica.
- O caminho do projeto contém acento e pode exigir ajuste em montagens.

## Evidência de validação

Pendente: provisionamento da VM, snapshot e teste de isolamento.
