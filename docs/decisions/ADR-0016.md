# ADR-0016 – Dashboard local somente leitura para demonstração

**Data:** 2026-11-16
**Status:** aceito

## Contexto

O MVP já entregava o ciclo completo pela CLI: iscas -> spool JSONL -> SQLite ->
lista de ban. A especificação mestre prioriza CLI e admite uma página local
simples, mas exclui um dashboard web sofisticado do MVP. Para demonstrar o
produto sem exigir que a plateia acompanhe comandos no terminal, faltava uma
visualização imediata do estado do agente, dos eventos e dos IPs observados.

A interface também não podia ampliar a superfície de ataque: nada de listener
exposto, autenticação fraca, escrita sem auditoria ou dependências pesadas.

## Alternativas

1. Manter apenas a CLI e demonstrar com `events list`/`bans list`.
2. Adicionar FastAPI/Uvicorn e uma aplicação web completa com ações de decisão.
3. Criar um dashboard somente leitura com a biblioteca padrão (`http.server`) e
   assets embutidos, restrito a loopback.
4. Criar apenas um TUI com `curses`/Rich.

## Decisão

- Novo comando `sentineliot serve` (aliases `web` e `dashboard`) que sobe um
  servidor HTTP local com `ThreadingHTTPServer`.
- A interface é **somente leitura**: não existe endpoint para decidir banimento,
  alterar configuração, iniciar/parar iscas ou aplicar firewall.
- O padrão é `127.0.0.1:8787`. `--host` fora do loopback exige `--allow-remote`;
  a interface não tem autenticação e não deve ser publicada.
- Os dados são lidos do mesmo SQLite, spool e `runtime.json` do agente. Cada
  requisição abre e fecha uma conexão curta, mantendo o agente como único
  escritor e evitando problemas de thread do SQLite.
- A API expõe `GET /api/summary`, `GET /api/events`, `GET /api/suspects`,
  `GET /api/events/<id>` e `GET /healthz`. Métodos de escrita retornam `405`.
- O HTML, CSS e JavaScript ficam embutidos em `web/assets.py`, sem CDN, sem
  fontes externas e sem uma etapa de build. A atualização é por polling
  configurável (`--refresh`, 1 a 60 s).
- `serve --demo` grava um cenário de demonstração somente quando o banco está
  vazio, reutilizando o spool e o coletor existentes.

## Justificativa

Atende ao critério de interface mínima sem introduzir dependências de runtime,
sem duplicar persistência e sem criar um segundo caminho de decisão. A
biblioteca padrão é suficiente para um painel local de leitura, mantém o wheel
simples e preserva a regra de não expor administração à Internet. Como não há
escrita, o pior caso de uma falha na interface é exibir dados desatualizados.

## Consequências

- Nenhuma dependência nova em `pyproject.toml`.
- O dashboard é demonstrativo e operacional, mas não substitui a CLI para
  auditoria e decisões.
- O `--demo` não altera bancos com eventos; para recriar o cenário é preciso
  usar outro diretório de dados.
- A CSP precisa permitir script e estilo inline por causa dos assets embutidos;
  em troca, não há origem externa nem conteúdo de terceiros.
- Testes cobrem os payloads, as rotas, os cabeçalhos, o `405` e a recusa de
  host fora do loopback.

## Riscos

- Interface sem autenticação: mitigada por escutar apenas loopback e recusar
  host remoto sem uma flag explícita.
- Polling contínuo em bancos grandes: mitigado por limites (`40` eventos e
  `40` IPs no resumo, `500` no máximo por consulta) e por não recalcular
  `quick_check` a cada atualização.
- Exposição acidental de IPs internos em uma tela compartilhada: o operador deve
  tratar o painel como informação sensível e encerrá-lo após a demonstração.
- Divergência visual entre navegadores: mitigada por HTML/CSS/JS sem framework e
  por recursos amplamente suportados.
