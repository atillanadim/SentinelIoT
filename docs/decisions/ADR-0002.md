# ADR-0002 — Protocolo e portas do honeypot inicial

**Data:** 2026-11-08
**Status:** aceito

## Contexto

O MVP precisa de uma isca de câmera IP que seja simples, observável e segura.
RTSP e ONVIF aumentam o realismo, mas também a complexidade e a superfície de
ataque.

## Alternativas

1. HTTP genérico em porta de laboratório.
2. RTSP desde o início.
3. ONVIF/HTTP.
4. Múltiplos perfis simultâneos.

## Decisão

- Primeiro perfil: `camera_simulator`.
- Protocolo: HTTP genérico.
- Porta padrão: 8080/tcp, configurável.
- Página de login genérica, sem marca real.
- Endpoints iniciais previstos: `/`, `/login` e respostas controladas para
  métodos e caminhos.
- RTSP e ONVIF ficam para evolução posterior.

## Justificativa

HTTP permite implementar o perfil com biblioteca padrão do Python, sem imitar
marca, sem capturar credenciais e com superfície mínima. É suficiente para o
critério do MVP: conexão de teste gera evento estruturado.

## Consequências

- O honeypot será menos realista que uma câmera RTSP real.
- A porta 8080 precisa ser publicada apenas no laboratório.
- A configuração deve permitir trocar a porta.
- A Fase 1 deve validar portas e isolamento.

## Riscos

- Um atacante pode identificar a isca como simulada.
- HTTP pode atrair menos interações que RTSP.
- A publicação de porta pode conflitar com serviços do host.

## Evidência de validação

Pendente: teste de inicialização e conexão controlada na Fase 1.
