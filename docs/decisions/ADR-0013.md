# ADR-0013 – Provisionamento offline da VM de laboratório

**Data:** 2026-11-08
**Status:** aceito

## Contexto

O laboratório deve operar sem egress para a Internet. A VM `sentinel-lab`
precisa de Git, Python 3.11.16, uv e Docker sem depender de repositórios
remotos durante a instalação. O host Windows pode baixar e validar artefatos;
a VM não deve ter rota padrão.

## Alternativas

1. Dar NAT temporário à VM apenas durante a instalação e remover depois.
2. Instalar tudo manualmente por console, copiando arquivos um a um.
3. Montar um bundle offline em ISO com repositório APT local, binários e
   wheels, e executar um instalador único.
4. Usar imagens de container prontas para toda a toolchain.

## Decisão

- A VM permanece **sem NAT, sem bridge e sem gateway padrão** durante todo o
  ciclo de vida.
- O host baixa e valida os artefatos; o bundle é gravado em um ISO
  `SENTINELBUNDLE`.
- O ISO contém:
  - repositório APT local com `Packages`/`Packages.gz` para Git,
    ferramentas de diagnóstico e dependências;
  - CPython 3.11.16 standalone (`python-build-standalone`), com SHA-256
    conferido;
  - uv 0.12.5 para Linux x86_64;
  - Docker Engine 29.9.3 static, Docker Compose v5.6.1 e a imagem
    `hello-world` salva com `docker save`;
  - wheels `cp311`/manylinux para as dependências fixadas do projeto;
  - cópia do código-fonte sem `.git` e sem `.venv`;
  - `install.sh` idempotente.
- O Docker é instalado a partir dos binários estáticos oficiais e gerenciado
  por uma unit systemd própria, porque o pacote `docker-ce` exigiria
  repositório remoto e dependências adicionais.
- As fontes APT online da VM são desabilitadas e permanecem apenas com o
  repositório local.

## Justificativa

Mantém o isolamento desde o primeiro boot, elimina variação de rede e produz
um processo repetível e auditável. Os artefatos são verificáveis por hash no
host.

## Consequências

- O bundle precisa ser regenerado quando versões mudarem.
- O Docker static não recebe atualizações automáticas; atualização é manual e
  documentada.
- Sem repositório Ubuntu online, pacotes fora do bundle não podem ser
  instalados até que sejam adicionados ao repositório local.
- `pip-audit` continua sendo executado no host, pois depende de base externa
  de vulnerabilidades.

## Riscos

- Divergência entre o ambiente do host e o da VM.
- Binários estáticos exigem validação explícita de funcionamento
  (`docker info`, `hello-world`, `pytest`, `ruff`, `mypy`).
- ISO e bundle ocupam espaço em disco e não devem ser versionados.
